# PostgreSQL 时间使用约定

`now()`、`CURRENT_TIMESTAMP`、`transaction_timestamp()` 返回事务开始时间；`statement_timestamp()` 返回当前语句开始时间；`clock_timestamp()` 返回调用时的数据库实际时间，同一语句内多次调用也可能得到不同值。依据：[PostgreSQL 16 时间函数说明](https://www.postgresql.org/docs/16/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT)。

| 场景 | 当前规则 |
| --- | --- |
| 执行权、旧租约、总期限 | 先取得任务行锁，再单独采样 `clock_timestamp()`；持久写入结束前重新校验。不能用事务时间或锁等待前计算的时间代替。 |
| 新任务创建、首次认领、续租 | 一次操作使用 `WITH clock AS MATERIALIZED (SELECT clock_timestamp() AS at)`，让相关时间字段和期限共享时基。认领和续租的采样发生在目标任务行锁已取得之后；创建无已有任务行锁。 |
| 候选认领 | 筛选查询的采样只用于选候选；取得候选锁后，UPDATE 使用新的时间值再次检查可用时间、队列期限和已有执行期限。超期不增加 attempts，不生成执行 token；恢复保留第一次开始时间和总期限。 |
| 过期尝试恢复、可重试失败 | 恢复回执验证结束后重新读取实际时间；恢复和重试的重新排队 UPDATE 再要求执行期限有效，超期按对应任务超时结算。 |
| Worker 心跳 | 首次登记和冲突更新显式使用实际时间。冲突更新使用自己的 `clock_timestamp()`，不复用可能在唯一约束／行锁等待前生成的 EXCLUDED 时间。 |
| 文档删除 | 先 SELECT FOR UPDATE，之后记录实际删除时间；重复删除保留首次时间。仅更换 UPDATE 表达式中的函数不能保证表达式在锁等待后才求值。 |
| 模型／工具调用开始、Manifest 捕获 | 写入时显式采样实际时间，覆盖历史 schema 的 `now()` 默认值，避免锁等待使时间线提前。 |
| Worker 状态、队列汇总、doctor 期限报告 | 操作开始时采样一次实际时间，作为所有相关查询的同一个参数。不会因事务开始时间过旧漏报，也不会在同一报告内使用不同时间阈值。 |
| 清理七天前的 Worker 记录 | 使用 `statement_timestamp()` 作为整条清理语句的固定阈值；锁等待不会导致清理扩大到更新后的记录。 |
| 普通业务记录、审计记录的 created_at 默认值 | 保留 `now()` 的事务时间语义，不参与当前执行权判断。 |

固定观察时间与数据库数据快照是两个不同概念。状态报告复用一个时间阈值，仍然是 READ COMMITTED 下的观察数据，不作为执行许可或原子系统快照。RAG 两路召回的一致性另由同一连接的只读 REPEATABLE READ 事务保证。

数据库实际时间来自服务器墙钟，不能保证免受系统时钟调整影响。跨进程持久期限继续以数据库时间为准；本地等待、调用和退出预算继续使用单调时钟，并遵守已有总期限限制。未将数据库时间函数当作本地计时器。

本次调整只修改业务 SQL，没有改写历史时间字段或已发布的迁移；已有个人数据库无需新增 schema 迁移。相关回归位于 `tests/test_database_time.py`，使用实际锁等待、数据库时间边界和事务开始时间对照验证。
