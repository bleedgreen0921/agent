# 项目定位、能力现状与后续清单

更新日期：2026-10-08。本文依据当前仓库实现及已核验的本机 Docker 全量测试结果，描述当前能力；后续方向单独列出。

## 项目定位

> 面向个人科研工作流的可扩展 Agent 执行与证据分析平台，以自动调制识别的文献检索和实验对比为首个应用场景。

项目以持久 Run、服务端工具 Provider、确定性数据分析和可追溯结果为核心。Agent 负责理解任务、规划步骤、选择工具与组织答案；文献检索由独立 RAG 服务完成，实验条件核对与数值计算由程序完成。通用扩展方向由统一工具接口承载，当前已有 RAG 和实验分析两类内置 Provider。

当前应用面向个人研究者，解决“实验用时间 ID 命名、配置保存在长 YAML 中，查找对照与比较结果需要逐个核对”的问题。主要材料为 PDF 论文、Markdown 研究记录、YAML 实验配置及 CSV/JSON 结果。论文和研究记录进入 RAG；配置与结果进入实验工具。结果图的读取、绘制和解释属于后续能力。

现阶段是完成合成数据工程验收的科研平台 MVP。实验 Provider 支持约定的合成格式；真实训练日志接入、真实论文与实验联动评估、个人工作台和在线报告文件交付仍需补全。可扩展接口不等于已经支持任意任务、任意文件格式或任意编排。

## 个人使用与团队设计的关系

`team_id` 保留为底层授权和资料隔离边界。个人部署可创建一个团队作为自己的科研空间，并绑定实验根目录；团队 Key 用于独立 Run，用户 Key 用于个人会话与记忆。当前需要通过已有管理 API 手工创建团队和用户，尚未实现自动初始化的个人空间或隐藏团队配置的界面。

科研项目与团队是不同概念。实验 YAML 的 `run.project_id` 及文件根目录用于标识研究项目；当前一个实验根目录只能包含一个项目，一个 Worker 的实验 Provider 绑定一个根目录与一个团队。尚未实现独立科研项目管理 API、多项目工作区或项目级资料关系模型。

## 当前分层与职责

| 层 | 已有实现 | 职责与边界 |
| --- | --- | --- |
| Agent 执行核心 | FastAPI Run/会话 API，LangChain/LangGraph，PostgreSQL | 持久排队、执行、预算、取消、恢复、最终结果发布 |
| 工具扩展层 | `module:factory` Provider；统一中间件 | 注入可信身份、预留调用额度、记录 trace、处理错误、收集证据 |

| 科研应用入口 | Run/会话 API、合成演示、离线导出脚本 | 当前通过 API 与脚本使用；前端和在线文件产物接口待实现 |

身份管理路由挂载在 RAG 管理面；数据库分为 `identity`、`rag`、`agent` 三个 schema。`experiment_service` 是共享 Python 模块，不是单独部署的 HTTP 服务，也没有独立数据库 schema。

## 已实现的科研场景

典型任务：

> 找出与 20261001_090000 仅在注意力开关上不同的实验，列出配置差异，比较总体、低 SNR 和各 SNR 准确率，列出基线最常见错分，并说明依据。

当前实验链路为：

```text
自然语言任务
  → Agent 选择实验工具
  → 首次登记 YAML/CSV/JSON 并保存本 Run 的不可变输入快照
  → 按 YAML 字段查找、按全部有效配置核对差异
  → 筛选完整有效的对照
  → 整数计数对账、加权计算、错分排序
  → 返回带文件路径/哈希与计算口径的实验证据
  → Agent 生成 answer/claims/citations/notices
  → 在数据库事务中发布结果与引用快照
```

配置比较仅忽略 `run` 元数据，保留数据划分、seed、类型、缺失字段和列表顺序。指标比较要求输入为 `ready`，差异集合恰好等于声明变量，评测人口与统计口径一致。总体准确率为 `sum(n_correct)/sum(n_total)`，低 SNR 固定为 SNR≤−5 dB，差异以百分点表示。

合成数据共 12 个实验：9 个 `ready`、1 个训练失败、1 个结果不完整、1 个缺少条件。基线总体 70%，仅开启注意力为 75.5%，相差 5.5 个百分点；低 SNR 差异为 11 个百分点。所有值是固定验收材料，不代表训练效果或真实科研结论。

每 Run 的输入快照使同一任务及恢复沿用已读取的数据，新 Run 才重新扫描目录。快照不是跨 Run 的常驻实验库，也不保证目录内所有文件在同一时刻原子读取；训练程序应写完结果后再提交分析任务。文件哈希能够核对来源，但没有存储全部原文件字节用于任意复演。

## 当前边界

| 方面 | 已有范围 | 尚未覆盖 |
| --- | --- | --- |
| 实验输入 | `schema_version: 1`、`synthetic: true`，约定 YAML/CSV/JSON 格式 | 真实训练框架日志、有效配置合并、任意字段格式适配 |
| 实验登记 | 每 Run 文件目录登记与固定快照 | 常驻实验索引、增量导入、独立实验 CRUD API、多根目录 |
| 检索 | 点路径精确类型匹配、状态过滤、分页 | 范围条件、指标排序、自然语言字段字典、保存检索条件 |
| 比较 | 单对严格配置差异、样本加权准确率、按 SNR 与错分计数 | 多 seed 汇总、置信区间、显著性检验、配对样本分析 |
| 文件结果 | 在线返回结构化 Run JSON；离线生成 Markdown/CSV | 在线生成与下载文件、产物版本和产物引用 |
| 文献与实验联动 | 两类工具可共同启用，统一证据结构 | 真实论文和实验联合任务的质量评估、方法与实验关系管理 |
| 图像 | 当前合成数据不包含结果图 | 绘制科研图、图像内容提取、读图与数值交叉核对 |
| 使用入口 | 团队 Run、个人会话 API 和脚本 | 个人工作台、自动默认空间、实验列表和可视化对比界面 |
| 扩展策略 | 部署级 Python Provider，两个固定执行模式 | 按项目工具策略、工具健康协议、模式插件、动态重规划 |
| 运行治理 | 调用次数与时间预算、安全恢复、只读诊断 | token/成本预算、工具级预算、受控重试 Run、修复/清理闭环 |

当前共享文件目录适合单机部署，文件与数据库不处于统一事务。运行角色对 Manifest、记忆与实验输入快照只允许 `SELECT/INSERT`，普通业务 trace 仍可修改；这些机制提供执行可追溯性，不构成完整不可篡改审计系统。

程序保证引用 ID 来自本 Run，并保存对应来源；尚未自动证明每条 claim 被证据语义充分支持，也未证明答案所有重要陈述都进入 claims。真实模型的工具选择、复杂文献理解、跨来源推理和最终表达需要专门评估。

## 验证状态

2026-10-08 修复后本机 Docker 全量测试完成：217 项通过，0 失败、0 错误、0 跳过；三个实验数据库专项用例全部通过。PostgreSQL 为真实容器数据库，模型为脚本化替身，真实 HTTP transport 被阻断。迁移、角色权限、checkpoint 及 doctor 的 15 项初始化诊断均通过。

该结果验证当前合成流程的工程机制，不代表真实模型效果、真实训练结果、真实论文检索质量或生产负载能力。详细证据、版本和复现步骤见[验收记录](validation-status.md)。仓库配置了 PostgreSQL CI 工作流，但此处记录的是本机实际运行结果，不宣称远端 CI 已执行。

## 后续补全清单

### 优先级 1：接入真实实验并交付文件

| 工作项 | 完成标准 |
| --- | --- |
| 真实数据格式适配器 | 至少一种实际训练输出转成标准实验记录；保留原始路径、有效配置与原指标单位 |
| 有效配置来源规则 | 核对独立 YAML、默认值与命令行覆盖；无法确认生效配置时标记条件未知 |
| 常驻实验索引与增量导入 | 时间 ID、配置指纹、文件哈希、状态可跨 Run 查询；重复/更新可识别 |
| 扩展筛选 | 支持 SNR/时间/学习率范围与指标排序；仍保留精确类型判断 |
| 多 seed 分析 | 去除同配置同 seed 重复记录，核对评测条件，按明确口径汇总均值与波动 |
| Artifact 工具 | Agent 导出 Markdown 报告和 CSV 表格，产物与 Run/输入快照/计算方法绑定 |
| 受控文件下载 | 下载权限与 Run 所属空间一致；API 返回产物元数据与可用下载入口 |

### 优先级 2：形成个人科研工作台

| 工作项 | 完成标准 |
| --- | --- |
| 个人空间初始化 | 首次创建默认团队/用户，使用入口简化，同时保留底层鉴权 |
| 科研项目模型 | 明确项目、实验、论文、研究记录与产物关系；项目不直接等同团队 |
| 实验浏览与对照界面 | 按条件查找时间 ID、展示关键配置与完整差异、查看异常状态 |
| 科研图生成 | 输出准确率-SNR 曲线、混淆矩阵等标准图，并绑定绘图数据和计算口径 |
| 真实资料联动验收 | 同一任务使用论文来源和实验文件来源，人工核对结论支持性 |
| 自然语言任务评估集 | 用真实模型检查工具选择、条件遗漏、错用指标与虚构引用 |

### 优先级 3：按需求扩展平台能力

| 工作项 | 完成标准 |
| --- | --- |
| 工具配置与策略 | 有实际第三类工具后，增加按项目的工具集合、配置校验与健康状态 |
| 模型策略 | 按规划/执行/最终生成区分服务端策略，并记录非秘密模型配置 |
| 受控失败重试 | 创建关联旧 Run 的新任务，明确重复调用和副作用语义 |
| 运维修复与清理 | 从只读 doctor 发展为可审查的孤儿文件、过期任务和数据保留处理 |
| token/成本与工具预算 | 指标和真实负载足以支撑时增加资源策略，保留现有统一调用记录 |
| 编排扩展 | 出现明确任务需求后再增加重规划、审批或专用流程 |

推进顺序以个人真实痛点和可验收任务为准：先让实际实验能查找、能比较、能导出，再扩展工作台与通用策略。当前阶段优先复用既有 Runtime、鉴权、工具注册和证据机制。
